# 人脸识别签到系统 — 提示词总结

> 项目全程使用 Claude Code (Anthropic Claude) 进行 AI 辅助开发

---

## 一、项目启动与架构设计

### 1.1 初始需求

```
我想做一个基于 InsightFace_Pytorch 的人脸识别会议签到系统，该怎么做？
```

**回复要点**：Claude 提出了完整架构方案，包括 Flask 后端、Web 管理后台、MTCNN + MobileFaceNet 识别流程、签到记录管理。

### 1.2 前端设计

```
可不可以给我设计一个交互容易便捷的前端页面？
```

**回复要点**：设计了 SPA 风格的管理后台，包含侧边栏导航、课程管理、人员管理、签到管理等功能。

### 1.3 多人签到优化

```
签到页面可以多人签到，不会一个人就要确认一下太慢了
```

**技术实现**：改为 MTCNN 的 `align_multi()` 同时检测多张人脸，每帧处理多人，无需逐人确认。

## 二、功能迭代提示词

### 2.1 微信小程序开发

```
我想基于这个项目开发一个微信小程序教师端可以拿着手机对班级内学生进行签到
```

**实现内容**：创建完整微信小程序（课程列表、摄像头签到、签到结果），新增移动端 API。

### 2.2 术语重构

```
全部改成最优方案。会议改成课程，部门改成班级，人员改成学生
```

**改动范围**：全局重命名，`meeting`→`course`，`department`→`class`，`person`→`student`，涉及数据库路径、API 路由、代码变量。

### 2.3 学生自主注册

```
加一个学生自主注册吧，自拍加输入自己姓名，可以以二维码的形式向学生传递上传
```

**实现**：创建 `/register/<name>` 注册页面，生成 QR 码，学生扫码→自拍→输入姓名→自动注册。

### 2.4 班级独立于课程

```
课程管理的班级部门添加业务逻辑不正确，是把整个班级的学生加入课程，
而且还有一个问题没有课程就不能有班级是不对的，班级是可以独立存在的
```

**重构**：全局班级注册表 `data/classes.json`，班级独立于课程存在，课程通过关联引用班级。

### 2.5 全局学生管理

```
学生信息也应该要有学生照片
学生管理把部门改成班级，与班级可以关联
删除学生同时删除其注册
```

**实现**：全局学生索引 `data/students_index.json`，全局学生照片 `data/students/photos/`，学生独立于课程 CRUD。

### 2.6 签到次数（Session）

```
同一个课程可以有多次签到啊对不对
签到应该按次来，课程，新建签到，命名第x次签到
```

**实现**：`sessions.json` 机制，每次签到独立记录，按 `course + session` 双重隔离。

## 三、问题修复提示词

### 3.1 路径编码问题

```
[Errno 2] No such file or directory: 'mtcnn_pytorch/src/weights/pnet.npy'
```

**修复**：CWD 改为 `core/` 目录，`config.py` 路径改为绝对路径。

### 3.2 模型加载路径

```
[Errno 2] No such file or directory: 'work_space\save\model_mobilefacenet.pth'
```

**修复**：`_get_conf()` 中修正 `work_path`、`model_path`、`save_path` 为基于 `_PROJECT_ROOT` 的绝对路径。

### 3.3 模型名双前缀

```
model_model_mobilefacenet.pth
```

**修复**：`load_state(conf, 'mobilefacenet.pth', True, True)` 传文件名，不要传 `model_path.name`。

### 3.4 Python 版本兼容

```
TypeError: unlink() got an unexpected keyword argument 'missing_ok'
```

**修复**：Python 3.7 不支持 `missing_ok=True`，改为 `if path.exists(): path.unlink()`。

### 3.5 跨课程签到干扰

```
别的课程签到后，另一个课程也会显示已签到
```

**修复**：`checkedSet` 按 `course + session` 过滤，实时页面每次重新加载时清空 `checkedSet`。

### 3.6 GBK 编码崩溃

```
UnicodeEncodeError: 'gbk' codec can't encode character
```

**修复**：`start_all.py` 中 `print` 避免使用 emoji，改为 ASCII 安全字符。

## 四、架构重构提示词

### 4.1 班级特征库

```
能不能把特征库在班级构建，而不是在课程构建，
这样任意课程导入班级学生后不用再重复构建特征库
```

**重构**：新增 `data/class_faces/` 目录，按班级构建特征库，课程关联班级后自动使用。中文目录名改用 hash（PyTorch 在 Windows 不支持中文路径）。

### 4.2 签到管理简化

```
只使用班级特征库，然后课程导入班级自动导入该班级特征库，
取消后台管理的签到管理，因为我使用班级构建特征库
```

**简化**：移除课程级特征库构建按钮，签到管理 tab 只显示报告和明细。签到接口自动降级到班级特征库。

### 4.3 实时签到页面优化

```
实时签到的结果不对，实时大屏是正常显示准确结果
```

**修复**：实时签到页面列表从空开始，只显示当前页面识别过程中签到的人。历史数据去签到结果页查看。

## 六、开发模式总结

### 6.1 交互模式

本项目采用 **对话式开发**（Chat-Driven Development）模式：

```
用户提出需求 → Claude 设计方案 → 用户确认 → Claude 编码实现
→ 用户测试反馈 → Claude 修复问题 → 循环迭代
```

### 6.2 提示词特点

| 类型 | 特点 | 示例 |
|------|------|------|
| 需求型 | 描述目标而非方案 | "我想做一个人脸识别签到系统" |
| 反馈型 | 报告问题现象 | "识别速度太慢了" |
| 纠正型 | 指出设计偏差 | "班级是可以独立存在的" |
| 优化型 | 要求改进 | "重现设计小程序整体布局" |

### 6.3 关键数据

- **总对话轮次**: 200+
- **代码文件**: 50+ 个
- **Bug 修复**: 20+ 次
- **架构重构**: 3 次（单体→核心分离、路径统一、班级特征库）
- **API 路由**: 80+ 条
- **小程序页面**: 7 个
